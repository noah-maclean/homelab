## Pi-hole — Tailscale Global DNS ✓

- Configured [[pihole|Pi-hole]] (`100.75.28.2`) as a [[tailscale|Tailscale]] global nameserver for ad-blocking everywhere
- Initial state: `dig` from Mac timed out; Pi-hole logs showed `ignoring query from non-local network 100.x.x.x`
- Root cause: Pi-hole v6 dnsmasq defaults to **"Allow only local requests"**, which drops DNS queries from Tailscale IPs
- Fix: Set Pi-hole web UI → Settings → **Permit all origins** (safe behind home NAT/firewall)
- DNS queries from Tailscale clients (Mac, phone, etc.) now route through Pi-hole correctly
- Created `containers/pihole.md` with config details and troubleshooting table
- Upstream DNS switched from Google DNS (`8.8.8.8`) to Quad9 filtered + Cloudflare (both DNSSEC)
- **macOS quirk found**: Tailscale network extension intercepts LAN IP traffic to tailnet peers even when Tailscale app is quit. Workaround: use Tailscale IP (`100.94.37.116`) for SSH to Hermes, or `systemextensionsctl deactivate` the extension
- Tailscale menu bar icon missing after brew + App Store version conflict — root cause was macOS **Menu Bar** settings blocking it in System Settings → Control Center

## Todo Reordering Automation

Created a cron-pipeline step that automatically reorders checkboxes in todo files:

- **Script**: `~/.hermes/scripts/reorder-todos.py` — scans all `vault/todo/*.md` files on every vault sync cron tick
- **Behaviour**: within each `##` section, moves `- [x]` completed items below `- [ ]` active items. Fully-done sections get ✓ appended to the heading
- **Pipeline**: integrated into `hermes-vault-diff-check.py` (the detection script). Runs after git pull, before the LLM agent. If reordering happened, the tidy-up is auto-committed and pushed as `chore: reorder todo checkboxes (active before completed)`
- **No-detect impact**: if reordering is the only change, it triggers the agent (so it can sync completions into container notes)

## Tailscale on Hermes — `--accept-routes` Fix ✓

- [[tailscale|Tailscale]] installed on Hermes LXC; Hermes joined tailnet as `100.94.37.116`
- Other Proxmox containers could no longer reach Hermes via LAN IP (`192.168.1.23`) — SSH and pings hung
- Pi-hole stayed accessible despite also having Tailscale — it doesn't accept routes
- **Root cause**: Hermes had `--accept-routes` enabled (default), which accepted the `192.168.1.0/24` subnet route advertised by the Tailscale LXC. This added `192.168.1.0/24 dev tailscale0` to table 52, routing all LAN-bound responses through the Tailscale tunnel instead of `eth0` — responses never reached the other containers
- **Fix**: `sudo tailscale set --accept-routes=false` — removed the `192.168.1.0/24` route from table 52 instantly
- Also set `sudo tailscale set --operator=$USER` so future commands don't need `sudo`

### Raycast Launcher Script

Created a Raycast script command at `~/.config/raycast/scripts/hermes.sh` for quick launching:

```shell
#!/bin/bash

# @raycast.schemaVersion 1
# @raycast.title Hermes
# @raycast.mode silent
# @raycast.icon /Applications/Hermes.app/Contents/Resources/icon.icns
# @raycast.description Launch Hermes Desktop
# @raycast.author hermes

export PATH="$HOME/.local/bin:$PATH"
hermes desktop
```

- Uses `hermes desktop` (the CLI command) to bypass the app's first-run provisioning check — avoids the reinstall screen issue on cold launch
- Accessible from Raycast by typing `herm` + Enter, or via Spotlight if Raycast is set as the default launcher
- Uses the native Hermes app icon from the app bundle
