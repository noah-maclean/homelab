# 06/08/2026

## OpenWhispr — local dictation app (Mac)

Installed **OpenWhispr** on the daily-driver Mac (2026-08-06) — an open-source (MIT), cross-platform (macOS/Windows/Linux) Electron app: effectively a free, privacy-first WisprFlow alternative. Website: openwhispr.com · repo: github.com/OpenWhispr/openwhispr.

- **Local engines** — `whisper.cpp` (Whisper tiny/base/small/medium/large + turbo, GGML, Metal-accelerated on Apple Silicon) and `sherpa-onnx` for NVIDIA **Parakeet** / **Nemotron** (~630–680 MB models, faster on laptops, streaming variants available).
- **Cloud BYOK providers** — OpenAI, Groq (whisper-large-v3-turbo), xAI (Grok STT), Mistral, Tinfoil, Corti, OpenRouter, Anthropic/Gemini; plus OpenWhispr Cloud free tier (2,000 words per rolling 7 days).
- **Per-mode engine selection** — Dictation / Note Recording / Audio Upload each keep their own engine choice (Settings → Speech-to-Text).

Decisions:

- Primary local model: **whisper large-v3-turbo** (~1.6 GB) — near-large accuracy (≈2.5% WER) at ~8× speed, comfortable on Apple Silicon.
- **Parakeet** (`parakeet-tdt-0.6b-v3`) kept as the speed-focused alternative for dictation.
- **Groq key deliberately not connected** — preference to keep all dictation audio on-device. Note: Groq ≠ Grok — Groq serves OpenAI's open Whisper weights, so cloud vs local turbo is the *same model*; zero accuracy difference, only speed/battery/privacy trade-offs. The Groq key can be added later as a complement for instant dictation without changing quality (same weights [[hermes_agent|Hermes]] already uses for Discord voice notes).

## [[immich|Immich]] — successful reinstall (container 104)

Reinstalled via community-scripts, now working at `http://192.168.1.25:2283`.

**What worked and why:**

- **Install** — Pi-hole OFF, 6 GB RAM during the source build (libjxl/libheif/libraw/ImageMagick/libvips), 4 cores; dropped to 4 GB RAM after. Container 104, IP `192.168.1.25` (host is `.20`, `.23` is the [[hermes_agent|Hermes]] LXC).
- **Storage** — `/mnt/storage/immich-photos` (mergerfs) bind-mounted at `/mnt/immich-photos`; `IMMICH_MEDIA_LOCATION` + upload symlinks pointed at the mount.
- **Crash-loop fix (the key lesson)** — `immich-web` kept dying on `Failed to read .../encoded-video/.immich` (ENOENT). The `.immich` marker files couldn't be written because **container root maps to host UID 100000**, so `chown`/`touch` as root inside the container fails on a bind mount. Fix: host-side `chown -R 100999:100991` + `chmod 775`, then create markers **as the immich user inside the container** (`runuser -u immich -- touch ...`).
- **Future reference:** on bind mounts in unprivileged LXCs, do file ops as the service user in the container (or as real root on the host) — never as container root.
- Added a verified, step-by-step **Install Instructions** section to [[immich]] (one command per step, host shell vs container, only the steps that worked).

## Jellyfin + Arr stack — architecture decided

Researched Docker-in-LXC vs Docker-in-VM and split-vs-combined for the media stack (Aug 2026), then updated [[todo_jellyfin_arr]]. Decision: **two LXCs** — Jellyfin native (community-scripts `jellyfin.sh`) plus the \*arr stack in Docker on an unprivileged LXC (community-scripts `docker.sh`, one compose file).

- **What worked and why:** PVE 9 fixed the runc/sysctl breakage that made unprivileged LXC + Docker unreliable on PVE 8 — so no privileged LXC (container root = host root) is needed. Community consensus: the \*arr suite belongs in one compose file (cross-talk, shared UIDs, version pinning); splitting Jellyfin out gives transcoding/resource isolation and independent restarts. ProtonVPN Plus confirmed — Gluetun's built-in NAT-PMP handles port forwarding, so the planned qsticky sidecar is obsolete.
- **Future reference:** if Docker-in-LXC breaks again after a host/kernel update, check runc sysctl handling first — that is the known fault line between LXC and VM for Docker workloads.
