- Installed user-local `npm@11.17.0` via `npm install -g npm@11.17.0 --prefix ~/.npm-global`

- `npm install` + `npm run build` in `~/hermes-agent/ui-tui` both succeed; `hermes --tui` launches

Note for future updates: if npm gets bumped into the blocked 11.10–11.16 range again, the user-local npm in `~/.npm-global/bin` (11.17.0) takes PATH precedence.

## [[hermes_agent|Hermes]] — Discord voice: ack + ambient bed enabled

Problem found during live VC test: the bot only *speaks* its final reply — intermediate tool calls land as text in the channel but are silent in the voice channel, so the user hears nothing for 30-60s while commands run.

Fix: enabled the built-in `voice_fx` subsystem (Discord-only feature, off by default):

```yaml
discord:
  voice_fx:
    enabled: true        # master switch
    ack_enabled: true    # speak a short phrase before tool calls
    ack_phrases: ["Let me look into that.", "One moment.", "Checking on that now.", "Give me a sec.", "On it."]
    ambient_enabled: true # subtle idle "thinking" bed while tools run
    ambient_gain: 0.18
```

Set via `hermes config set discord.voice_fx.enabled true` and `hermes config set discord.voice_fx.ack_enabled true`.

Caveats:

- Config is loaded at gateway start → needs gateway restart (`/restart` in Discord or `systemctl --user restart hermes-gateway`) + bot re-join VC to take effect.
- Acks are canned phrases on the first tool call of a turn, not live narration of what the agent is doing. No platform (CLI, TUI, Telegram, Discord) speaks tool-call narration; final reply only. True running narration would be a feature request upstream.

### 2026-08-05 — voice_fx tuning: ambient bed off

After restart + VC test: ambient bed (synthesised pad loop) was disliked and caused Whisper hallucinations. The bot's voice receiver only pauses during *speech* playback, not during the ambient loop — so the bot heard its own ambient audio and hallucinated lyrics ("Hey! Hey, I'm a little bit older…") that were never spoken.

- `hermes config set discord.voice_fx.ambient_enabled false` — kills the pad loop
- Voice is confirmed consistent: `tts.edge.voice: en-US-AriaNeural` is used by both ack and reply paths; no voice randomization exists in code. Perceived voice variation = random ack phrase selection from `ack_phrases` (5 phrases).
- Needs gateway restart to take effect.

### 2026-08-05 — LOCAL PATCH: Whisper hallucination filter

Extended `is_whisper_hallucination` in `~/hermes-agent/tools/voice_mode.py` to catch the first-utterance-after-join hallucinations (Whisper repeats filler phrases over near-silence during voice socket warm-up). Original filter only matched a fixed set of known phrases ("thank you", "subscribe", …) — missed real hallucinations like "It's a very good idea. It's a very good idea."

Changes:

- `_repeated_phrase_hallucination()` — flags any 4+ word contiguous sequence appearing 2+ times in one utterance (sliding window). Catches verbatim AND variant repeats (e.g. "I'm a little bit older … a little bit older!").
- Repeat-filler regex now requires 3+ filler words, so "okay okay" / "yeah yeah" pass as natural speech.
- Any single sentence that is itself a known hallucination phrase is flagged (catches "thanks for watching. thanks for watching.").

Verified with 18 test cases: all hallucinations caught, all natural speech/interjections/emphatic repeats preserved.

⚠️ **Local patch — must be re-applied after `hermes update`** (git checkout will overwrite). Diff is small; re-patch from this note if the file resets. Needs gateway restart to take effect.

### 2026-08-05 — LOCAL PATCH v3: trim leading silence before STT (replaces v2 drop)

User correctly rejected the v2 approach (dropping the first utterance after join eats real speech). Root cause re-examined: Whisper hallucinates plausible filler over **silent prefixes**, and the first utterance after a VC join carries a long silent head (voice-socket warm-up) — that's why every first message looked like clean-sounding nonsense regardless of content.

Real fix in `~/hermes-agent/plugins/platforms/discord/adapter.py`:

- Added `VoiceReceiver.trim_leading_silence()` — walks 20ms RMS windows over the raw 48k/stereo/s16le PCM, cuts everything before the first window exceeding RMS 200 (int16), keeps an 80ms lead-in for speech-onset context
- Applied in `check_silence()` when utterances complete: silent prefix trimmed before STT; all-silence buffers return `b''` and are skipped
- Removed the v2 drop-first-utterance hack entirely (init state, join reset, listen-loop guard)

Verified: 2s silence + 1s speech → trims to ~1.08s; all-silence → dropped; pure speech → untouched; quiet speech (amp 300) → kept. v1 phrase-filter retained as a second layer.

⚠️ **Outcome: v3 did NOT fix the first-utterance hallucination.** Live test (00:06 on 08-06): first utterance after restart still transcribed as *"I'm going to go to the next one."* — a known Whisper filler phrase. Diagnosis: the first utterance's audio is garbage/noise with energy (socket warm-up), not silence, so the trim keeps it and Whisper hallucinates over it. Proper fix needs real debugging (save first-utterance audio, inspect waveform, likely require sustained speech before treating as utterance). **Parked — see [[todo_hermes|Hermes TODO]].**

Trade-off: none for real speech — only silence is cut. First utterance after join should now transcribe correctly.

⚠️ Same re-apply-after-update caveat. Needs gateway restart.
